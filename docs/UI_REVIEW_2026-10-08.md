# Mobile UI review — 8 October 2026

## Findings and changes

| Area | Finding | Change |
| --- | --- | --- |
| Profile subscription; admin user detail actions; driver and subuser creation | Buttons constrained to 32–34 px inherited a 48 px minimum and 24 px vertical padding, clipping their labels. | Raised the affected screen actions to 48 px. `OpenVtsButton` also supports compact layouts without clipping, and disabled labels have stronger contrast. |
| Track Links | The 36 px New Link action clipped its text. | Increased the control to 48 px. Other short fixed-height actions in the geofence and track-link sheets were increased to 48 px. |
| User ↔ driver messages | Outgoing text inherited the page text color on a dark primary bubble. | Bubble background and every text element now use the matching `primary`/`onPrimary` pair. |
| User Operations calendar | Today's day number used a low-contrast container pair. | Today and selected day use the primary surface with on-primary text. |
| Admin Transactions | Selected status chip text could be dark on the dark selected chip. | Explicit selected and unselected chip, checkmark, and date-chip colors. |
| Shared controls | Selected detail tabs used a different dark-mode palette from segmented controls; compact actions, dropdowns, and text fields were reviewed against the shared theme. | Detail tabs now use the same `primary`/`onPrimary` selected pair as other controls. Existing dropdown and input components already use the shared input decoration and surface colors. |
| User Transactions and Vehicle Services | Filter and segmented controls had inconsistent selected colors; the service list hid transport errors behind a generic message. | Filter chips and shared segmented buttons now use the app color scheme. The service list allows longer reads and explains timeouts or connection failures. |
| User Transactions loading | Overlapping responses could let an older filter result replace the latest request. Old rows remained visible while a new filter loaded. The server defaults undated requests to the current month, so older entries can look missing. | Stale responses are ignored, first-page filters clear prior rows and get a fresh cache key, and history reads allow more time. Added an All Time filter and an action from the empty current-month state that supplies a start date. |
| Mobile notifications | The default notification sound was used. | Added the supplied tune to Android and a WAV conversion to the iOS bundle; configured local notifications and a new Android FCM channel. |

## Remaining validation

- No Android or iOS device is attached, so the screens and audio need on-device QA with the three roles and real data.
- The adjacent server source confirms the `/user/transactions` request and response shape. An unauthenticated request to the configured API returns HTTP 401 for that route, so a signed-in trace is still needed to diagnose missing transaction rows.
- The adjacent server source also defines `/user/vehicle-service/vehicles`, but the configured API currently returns HTTP 404 for that path even without authentication. This matches the Vehicle Services screenshot and indicates a deployment or routing mismatch; a mobile client change cannot supply the missing server endpoint.
- The backend FCM sender explicitly sets Android channel `open_vts_alerts` and APNs sound `default`. Background remote notifications need a sender change to use the new channel and custom iOS sound; the backend was kept read-only as requested. See [NOTIFICATION_SOUND.md](NOTIFICATION_SOUND.md).
- Whole-project analysis still reports pre-existing errors in the unused `account_closure_card.dart` and undeclared direct `timezone` imports in `user_operation_schedule.dart`. The Android app builds despite these analyzer findings.
