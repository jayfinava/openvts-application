CRITICAL ISSUE IDENTIFIED
================================================================================

ISSUE: Hardcoded Light-Mode Colors
SEVERITY: CRITICAL
INSTANCES: 170+
FILES AFFECTED: 18

PROBLEM:
  Light-mode colors were hardcoded throughout the widgets without any
  theme awareness. In dark mode, this caused:

  • Borders (#E7E3EA) invisible on dark background (#0F0D12)
  • Text (#141118) invisible on dark surfaces (#18141D)
  • Light surfaces (#F4F3F6) invisible in dark mode
  • Buttons and form fields difficult or impossible to see
  • User unable to interact with the page effectively

ROOT CAUSE:
  Developers used OpenVtsColors constants directly instead of using the
  context.isDarkMode extension method available in the theme system.

IMPACT:
  Dark mode was essentially non-functional for route optimization features.

================================================================================
RESOLUTION
================================================================================

SOLUTION: Theme-Aware Color System
  Replaced all hardcoded light-mode colors with conditional logic that
  selects the appropriate dark or light color based on the current theme.

IMPLEMENTATION PATTERN:
  OLD: color: OpenVtsColors.textPrimary
  NEW: color: context.isDarkMode
           ? OpenVtsColors.darkTextPrimary
           : OpenVtsColors.textPrimary

COLORS UPDATED:
  1. border           → darkBorder
  2. surface          → darkSurface
  3. surfaceElevated  → darkSurfaceElevated
  4. textPrimary      → darkTextPrimary
  5. textSecondary    → darkTextSecondary
  6. textTertiary     → darkTextTertiary

TOTAL REPLACEMENTS: 170+
