CRITICAL ISSUE IDENTIFIED
================================================================================

ISSUE: Hardcoded Light-Mode Colors in Notification Settings
SEVERITY: CRITICAL
INSTANCES: 68+
FILES AFFECTED: 9

PROBLEM:
  Light-mode colors were hardcoded throughout the notification settings
  widgets without any theme awareness. In dark mode, this caused:

  • Borders (#E7E3EA) invisible on dark background (#0F0D12)
  • Text (#141118) invisible on dark surfaces (#18141D)
  • Light surfaces (#F4F3F6) invisible in dark mode
  • Toggle switches appeared non-responsive
  • Channel configuration options invisible
  • Form labels and descriptions unreadable
  • User unable to configure notification preferences

ROOT CAUSE:
  Developers used OpenVtsColors constants directly instead of using the
  context.isDarkMode extension method available in the theme system.

IMPACT:
  Dark mode was essentially non-functional for notification management.
  Users could not configure push, email, or SMS notification preferences.

================================================================================
RESOLUTION
================================================================================

SOLUTION: Theme-Aware Color System
  Replaced all hardcoded light-mode colors with conditional logic that
  selects the appropriate dark or light color based on the current theme.

IMPLEMENTATION PATTERN:
  OLD: border: Border.all(color: OpenVtsColors.border)
  NEW: border: Border.all(
         color: context.isDarkMode
             ? OpenVtsColors.darkBorder
             : OpenVtsColors.border
       )

COLORS UPDATED:
  1. border           → darkBorder
  2. surface          → darkSurface
  3. surfaceElevated  → darkSurfaceElevated
  4. textPrimary      → darkTextPrimary
  5. textSecondary    → darkTextSecondary
  6. textTertiary     → darkTextTertiary

TOTAL REPLACEMENTS: 68+
